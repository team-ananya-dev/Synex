# What each of you gives your Claude Code

Your agents get context from files in the repo, not from this planning chat. Claude Code loads `CLAUDE.md` automatically at the start of every session. Everything else is read on instruction. So the "context transfer" is two things: the files in the pack, and the first prompt below.

Files an agent must be able to read (all in the repo after the first commit):

1. `CLAUDE.md` (loaded automatically)
2. `docs/context/00_PROJECT_CONTEXT.md` (everything decided so far)
3. `docs/context/01_RULEBOOK.txt` (the rules)
4. `docs/context/02_SITE_FLOW.md` and `03_BUILD_GUIDE.md` (the long specs, exported from the two documents; see `docs/context/README.md`)
5. `docs/TEAM_README.md`, `docs/AGENT_COMMS.md`, `docs/SETUP_RUNBOOK.md`
6. `docs/progress/<name>.md` and `docs/inbox/<name>/` (live status, once they exist)

The two phases are separate. Before the official start, an agent only reads and plans. After the start, you tell it the build has started.

## Prompt 0: orientation (before the build starts; both of you)

Paste into a new session in the repo. It writes no code.

```
I am <Dev|Ananya>. The build has NOT started, so write no code and create no files other than notes I ask for.
Read CLAUDE.md, docs/context/00_PROJECT_CONTEXT.md, docs/context/01_RULEBOOK.txt and docs/TEAM_README.md.
Then read docs/context/03_BUILD_GUIDE.md and docs/context/02_SITE_FLOW.md if they exist.
Reply with:
1. The product in 5 lines.
2. The rulebook rules that most constrain us, as a numbered list.
3. The files and directories I own, from TEAM_README section 3.
4. Three things in the plan that look risky or unclear to you.
5. Any contradiction between the documents.
Do not start designing yet.
```

Check the answer against the rulebook yourself. If an item is wrong, the agent has not absorbed the context; ask it to re-read the named file.

## Prompt W: a second session in a worktree (either of you)

Create the worktree yourself first (`git worktree add ...`, see `docs/TEAM_README.md` section 7.4), then start `claude --name <short-name>` inside it and paste:

```
I am <Dev|Ananya>. This is a second session in a git worktree on branch <branch>. Its single task is: <one sentence>.
Read CLAUDE.md, docs/context/00_PROJECT_CONTEXT.md, and the contracts/ files this task touches.
Work only in these files: <list of paths from my ownership table>. Do not edit anything else.
When the task passes its checks, tell me. Then run the rule-checker subagent on the diff and wait.
If you learn something another session of mine needs (a changed contract field, a finished module), send that session a short message, naming the file to read.
```

```
We are agreeing the contracts. Read contracts/ as it stands. For the area I own, list every route, event type and enum value that the other person's code must rely on, with exact JSON field names and types. ```
```

## Rules for all prompts

- Always say who you are. The ownership rules depend on it.
- Always say whether the build has started.
- Never paste keys or `.env` contents into a prompt.
- Do not ask any agent about the finals' unseen requests, and do not try to find them.
- After an agent finishes a task, ask it to explain the data flow in 10 lines and check the explanation against the code. Both of you must be able to explain every module at the finals.
